### Changed

- The LLM tools of `ebaml-mcp` (`describe_feature`, `describe_model`, `propose_difficulties`) await the async form of their LLM call, so the server answers other tool calls and runs several LLM calls at the same time.
- `describe_model` of `ebaml-mcp` ends its text with a `failed_features:` line that names each feature whose description failed, with its error. The server keeps no such partial text, so the next call asks again.
